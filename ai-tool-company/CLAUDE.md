# AI Tool Dev Co. - プロジェクト指示書

## 会社概要
業務効率化・DX系のツールを企画〜開発〜検証まで行う小規模開発チーム。
人間(あなた)が経営者/最終意思決定者となり、3人のAI社員(サブエージェント)が
それぞれの役割を分担して働く。

## AI社員一覧
| 役職 | エージェント名 | 主な仕事 |
|---|---|---|
| PM(企画・設計) | `pm` | 要件整理、仕様書作成、タスク分解 |
| 開発者(実装) | `developer` | 仕様に基づくコード実装 |
| QA(品質保証) | `qa` | コードレビュー、テスト、バグ検出 |

## 基本の仕事の流れ
1. あなたが「作りたいツールのざっくりした要望」を伝える
2. `pm` エージェントが要件定義書・仕様書(spec.md)を作成
3. `developer` エージェントが spec.md を読んで実装
4. `qa` エージェントが実装をレビュー・テストし、問題点を報告
5. 問題があれば developer に差し戻し、なければ完成

## ディレクトリ構成の想定
```
project/
├── CLAUDE.md              ← この指示書
├── .claude/agents/         ← AI社員(サブエージェント)定義
│   ├── pm.md
│   ├── developer.md
│   └── qa.md
└── projects/
    └── <ツール名>/
        ├── spec.md         ← PMが作成する仕様書
        ├── src/            ← developerが実装するコード
        └── qa-report.md    ← QAのレビュー結果
```

## 開発方針
- 対象ユーザーは主に一般業務職〜非エンジニアの社内スタッフ。専門知識がなくても使えるUI/UXを優先する
- 小さく作って動くものを早く出す(MVPファースト)。過剰な設計はしない
- コードのコメント・ドキュメントは日本語で書く
- 個人情報・機密情報を扱うツールでは、必ずQAでセキュリティ観点のチェックを行う

## エージェントの呼び出し方
Claude Codeは会話内容から自動でサブエージェントに処理を委任することもあるが、
明示的に呼び出したい場合は以下のように指示する。

- 「pmエージェントを使って、〇〇の要件をまとめて」
- 「developerエージェントに spec.md の内容を実装させて」
- 「qaエージェントにこのコードをレビューさせて」
