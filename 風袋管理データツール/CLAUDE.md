# 風袋管理データツール

フィールドを自由に定義できる汎用データ管理ツール。ビルド不要、ブラウザで直接実行できる構成にする。
アプリ内の表示名（`<title>`／見出し`<h1>`）は「FileData」（2026-07-26変更、元は「風袋管理データツール」）。複数データベース対応で用途が汎用化したことに伴う表記変更。このCLAUDE.md自体のタイトルやフォルダ名は元のまま。
参考にしている既存ツール: https://mydatabase-touseki.manus.space （「マイデータベース」＝カスタマイズ可能なDB管理ツール。透析患者の曜日／クール管理に使われている実例）。

## 技術スタック
- HTML / CSS / JavaScript（素のJS、フレームワーク不使用、単一 index.html）
- ビルドツールなし。ブラウザで index.html を直接開いて動作確認する
- データは localStorage に保存。複数データベース対応のため、データベースごとに名前空間化されたキー（`taretool_fields_${dbId}` = フィールド定義、`taretool_items_${dbId}` = データ本体、他に settings/history/snapshots も同様）を使用。データベース一覧は`taretool_databases`、現在選択中のIDは`taretool_active_db`に保存。ダークモード（`taretool_theme`）はデータベース非依存の全体設定

## 現在の状態（コア部分 実装済み）
- フィールド設定（⚙ボタン）: フィールドの追加・編集・削除・並び替え
  - 対応フィールド型: テキスト／長文／数値／日付／チェックする／選択肢（1行1つで選択肢を定義）
- データの登録・編集・削除（＋追加ボタン、各カードの編集／削除ボタン）
- 一覧表示（カード形式でフィールド値を表示）
- 初期フィールドは「品名／風袋重量／単位（g・kg）／メモ」をサンプルとして用意
- 表示設定（🗂ボタン、`taretool_settings`キーで保存）
  - 一覧のグループ化（最大3階層、`<details>`で開閉可能・未設定値は末尾グループにまとめる）
  - フォームビュー用のタイトル／サブタイトル項目の指定
- フォームビュー（トグルボタンで一覧⇄フォーム切替）: 1件ずつ表示し前へ／次へで移動（現在のグループ化順を反映）、編集／削除ボタン付き
- フィールド削除時は表示設定（グループ化・タイトル・サブタイトル）の参照も自動的にクリア
- ダークモード切替（🌙／☀️ボタン、`taretool_theme`キーで保存、`<html data-theme="dark">`をCSS変数で切替。`<head>`内の即時実行スクリプトで初期表示時のちらつきを防止）
- トースト通知（画面右下、追加/更新/削除やフィールド・表示設定の保存時に表示、`showToast(message, type)`）
- 予期しないJSエラーを検知した際の全画面フォールバック表示（`window.onerror`/`unhandledrejection`、再読み込みボタン付き）
- 検索・並び替え: ツールバーの検索欄（`searchInput`、リアルタイム絞り込み、全フィールドの表示値に対する部分一致・大小無視）と、表示設定モーダル内の並び替え項目／昇順・降順設定（`settings.sortFieldId`/`settings.sortDirection`）。一覧・グループ化・フォームビューいずれも検索結果＋ソート順を反映（`getVisibleItems()`が起点）。フィールド削除時は並び替え参照も自動クリア
- CSVエクスポート／JSONバックアップ（💾ボタン）: CSVエクスポートは現在の検索・並び替え適用後の一覧をUTF-8 BOM付きCSVとしてダウンロード（Excel文字化け対策）。JSONバックアップ書き出しはフィールド定義・全データ・表示設定を1ファイルにまとめて保存。JSONバックアップ読み込みはファイル形式を検証した上で確認ダイアログを出し、現在のデータを丸ごと置き換え
- 印刷（🖨️ボタン）: `@media print`でツールバー・モーダル・トースト・編集/削除ボタン・フォームナビを非表示にし、ダークモード中でも印刷時は強制的にライト配色（CSS変数を上書き）。押下時はフォームビューなら一覧表示に自動切替し、グループの`<details>`を全て開いてから`window.print()`。一覧上部に検索語・件数・出力日時を示す`#printMeta`（画面上は非表示、印刷時のみ表示）
- 追加フィールド型「区切り線」（`divider`）: データを持たない見た目だけのフィールド。フィールド編集モーダルで名前入力は任意（空欄可、プレースホルダー「見出し（任意・空欄可）」）。データ登録フォーム／一覧カード／フォームビューではラベル付き（or空欄なら1本線のみ）の水平線として表示（`.form-divider`/`.item-divider`）。グループ化・タイトル・サブタイトル・並び替えの項目選択（`populateFieldSelect`）や検索・CSVエクスポートの対象からは除外
- 追加フィールド型「複数選択」（`multiselect`）: 選択肢（1行1つ、`select`型と同じ入力欄・options共有）に対してチェックボックス一覧で複数選択。値は選択済み文字列の配列として保存。表示は`formatFieldValue`で「、」区切りの文字列に変換（一覧・フォームビュー・CSV共通）。グループ化・タイトル・サブタイトル・並び替えの選択肢からは除外（複数値のため単一値比較に馴染まない）
- 追加フィールド型「画像」（`image`）: `<input type="file">`でアップロードした画像をFileReaderでBase64のdata URLに変換しlocalStorageへ保存（1ファイル2MB上限、超過時はトースト警告して受け付けない）。フォームにプレビュー表示＋削除ボタン。一覧・フォームビューでは`<img class="item-thumb">`としてサムネイル表示、CSVでは`(画像あり)`のプレースホルダーテキストのみ出力。`saveItems()`はlocalStorage容量超過（QuotaExceededError）を`try/catch`で捕捉しトースト表示＋変更をロールバックする防御を追加（画像データ導入で容量超過リスクが生じたための対応）
- 追加フィールド型「計算式」（`formula`）: `{フィールド名}`で他フィールドを参照し、自作の再帰下降パーサー`safeEvalArithmetic()`で評価（`eval`/`Function`は不使用）。対応構文は四則演算`+ - * /`、括弧`( )`、比較演算子`> < >= <= == !=`（真偽をそれぞれ1/0の数値で返す）、関数`IF(条件, 真の場合, 偽の場合)`・`SUM(値1, 値2, ...)`（引数はいずれもカンマ区切りで任意個数の式を取れるが、IFは条件・真・偽の3引数固定）。値は保存せず表示・検索・CSV出力のたびに`evaluateFormula(f, item)`で都度計算（小数第2位で丸め、エラー時は`#ERROR`表示）。参照先フィールドは自身以外の通常フィールドのみ（区切り線/複数選択/画像/計算式/リレーションは参照不可、循環評価を回避）。フィールド保存時にダミー値でテスト評価し、構文エラー（未対応の関数名や引数の数の誤りなど）があれば保存前にアラートで警告。フィールド編集モーダルの計算式欄には参照可能なフィールド名の`<select>`と「＋挿入」ボタンを併設し（`populateFormulaFieldSelect()`）、選んで挿入するとカーソル位置に`{フィールド名}`が自動挿入される（手打ちでの誤字を防止する目的、直接キーボード入力も引き続き可能）
- 追加フィールド型「リレーション」（`relation`）: 同一データセット内の他の項目1件を参照する自己参照型（複数の「テーブル」を持たない本ツールの構成上、この形が最も自然な実装）。値は参照先項目のID文字列。フォームでは自分自身を除いた項目一覧から`<select>`で選択、選択肢ラベルは表示設定のタイトル項目（`getRelationLabel()`、未設定時は先頭の通常フィールド）から生成。表示は参照先のラベルをそのまま文字列として扱う（`formatFieldValue`に統合、検索・CSVも自動対応）。参照先の項目が削除された場合は`clearRelationReferences()`で全項目のリレーション値を自動的に空にし、ダングリング参照を防止
- 変更履歴／自動スナップショット（🕘ボタン）: データ（項目）の追加・更新・削除のたびに履歴へ記録（変更前後の値の差分`diffValues()`、最大200件、対象は通常フィールドのみで区切り線・計算式は対象外）。フィールド定義自体の変更（型追加・削除・並び替え等）は履歴に含まれない。自動スナップショットは項目の保存（`saveItems()`）のたびに全データのスナップショットを自動保存（最大5件、画像データは`(スナップショットでは省略)`に置換して容量を節約）。JSONインポートやスナップショット復元の直前にも明示的にスナップショットを取得し、復元前の状態に戻せるようにしている。履歴・スナップショットいずれもJSONバックアップの書き出し対象には含まない（ブラウザのlocalStorageに閉じた内部的な安全機能という位置づけ）
- 複数データベース対応（ヘッダーの`<select>`＋＋／🗄ボタン）: 「データベース」＝フィールド定義・データ・表示設定・履歴・スナップショットを丸ごと切り替えられる独立した名前空間（`taretool_databases`に`{id, name}`の配列で管理、現在の選択は`taretool_active_db`）。ヘッダーの`<select id="dbSelect">`で切り替え（`switchDatabase()`が`fields`/`items`/`settings`を再読込し検索語・表示モード等をリセットして再描画）、＋ボタンで新規データベース追加（新規IDに対しては初回アクセス時と同じサンプルフィールドが自動生成される）。旧バージョン（単一データベース構成）の`taretool_fields`等のデータが存在する場合は起動時に自動検出し、「データベース1」として新しい名前空間へコピー（旧キー自体は削除せず温存、非破壊的な移行）。ダークモードのみデータベース非依存でグローバルに共有
- データベース管理モーダル（🗄ボタン、`dbManageModal`）: 全データベースを一覧表示し、フィールド設定と同様の行UI（↑↓／✎／📋／🗑）で操作。**並び替え**は配列の隣接swap（`saveDatabases()`後に`<select>`にも反映）。**名前変更**は行ごとに任意のデータベースを対象にでき（`openDbModal('rename', dbId)`、選択中でなくても変更可）、現在選択中の行には「(選択中)」ラベルを表示。**複製**（`duplicateDatabase()`）は新規IDでfields/items/settingsのみをlocalStorage上でコピー（history/snapshotsは複製せず新規データベースとして真っさらから開始、名前は「〇〇のコピー」）。**削除**（`deleteDatabase()`）はfields/items/settings/history/snapshotsの全キーを`localStorage.removeItem`、確認ダイアログあり、選択中のデータベースを削除した場合は残りの先頭データベースへ自動切替、最後の1つは削除不可（アラートで警告）

補足: 以前このフォルダに置かれていたReact/TypeScript版の`App.tsx`（wouterルーティング・shadcn/ui・ThemeProvider・Toaster等の雛形のみで実体ページなし）はビルド環境（Node.js/npm、この環境には未インストール）が必要なため採用せず、その設計意図（テーマ切替・トースト通知・エラー時のフォールバック表示）だけを上記の形で素のJS実装に反映した。

## 既知の制約（発展させる場合の候補）
- リレーションは1件のみ参照可能な自己参照型（1対多・多対多は未対応、かつ同一データベース内のみ。データベースをまたいだリレーションは不可）。フィールド名変更で計算式の参照が壊れる
- 変更履歴・スナップショットはフィールド定義自体の変更（型追加・削除等）を追跡しない
- JSONバックアップの書き出し／読み込みは現在選択中のデータベース単位（データベース一覧全体を一括バックアップする機能はなし）。データベース複製は履歴・スナップショットを引き継がない（新規データベースとしてまっさらから開始）

## 進め方の注意
- 機能は一気に全部作らず、ユーザーが指定した1カテゴリずつ進める（例:「まずグループ化だけ」「次にCSV出力だけ」）。
