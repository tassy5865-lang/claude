# テスト環境の作り方(手順書)

予約システムを**本番に出す前に**、テスト用のスプレッドシート+カレンダーで動かすための手順です。
所要時間の目安は 40〜60分。作業はすべてオーナーのGoogleアカウントで行います。
**テスト中のメールは実際に送られます。`OWNER_EMAIL` と予約時のメールは自分宛てにしてください。**

> 動作確認の項目は `docs/deploy-checklist.md` の「2. 動作確認」(1〜12、39〜44 など)を使います。

## 0. 事前に決める値(メモしておく)

| 値 | 内容 | テストでの目安 |
|---|---|---|
| `OWNER_EMAIL` | 新規予約・キャンセルの通知先 | 自分のメール |
| `CALENDAR_ID` | テスト用カレンダーのID | 手順2で取得 |
| `SITE_URL` | 予約サイトの公開URL | `https://tassy5865-lang.github.io/claude/kohaku-booking/index.html`(仮でも可) |
| `ADMIN_PASSWORD` | 管理画面のパスワード | テスト用の文字列(本番とは別にする) |

## 1. スプレッドシートを作る
1. https://sheets.google.com で新しいスプレッドシートを作る。名前は `琥珀予約_テスト`。
2. メニューの「拡張機能 → Apps Script」を開く。

## 2. テスト用カレンダーを作る
1. https://calendar.google.com の左側「他のカレンダー」の `+` → 「新しいカレンダーを作成」。名前は `琥珀予約_テスト`。
2. 作成後、そのカレンダーの「設定と共有」→「カレンダーの統合」にある **カレンダーID**(`…@group.calendar.google.com`)をコピー。
3. 既定カレンダーを使うと個人の予定が空き判定に混ざるので、専用カレンダー推奨。

## 3. コードを貼り付ける
Apps Script のエディタで:
1. 左の「プロジェクトの設定(歯車)」→「『appsscript.json』マニフェスト ファイルをエディタで表示する」をON。
2. 左のファイル一覧に戻り、`appsscript.json` を開いて、`gas/appsscript.json` の中身で置き換える(タイムゾーン Asia/Tokyo、ウェブアプリ設定)。
3. `Code.gs` の中身を全部消して、`gas/Code.gs` の全文を貼り付ける。
4. 冒頭の `CONFIG` を編集:
   ```js
   CALENDAR_ID: '手順2でコピーしたID',
   OWNER_EMAIL: '自分のメール',
   SITE_URL: '予約サイトのURL',
   ```
   営業時間・定休日(水)などの仮置き値はそのままでOK(本番前に店主へ確認)。
5. 保存(Ctrl+S)。

## 4. スクリプト プロパティを設定
「プロジェクトの設定」→ 下の「スクリプト プロパティ」→「プロパティを追加」:
- `ADMIN_PASSWORD` = テスト用パスワード

LINE連携は後回しなので `LINE_*` / `LIFF_ID` は不要です。

## 5. 初期化を実行
関数の選択欄(上部)で順に選んで「実行」します。初回は権限の承認画面が出ます(「詳細」→「安全ではないページに移動」→ 許可。カレンダー・スプレッドシート・メール送信)。

1. `setup` … `予約` / `顧客` / `クーポン` / `メニュー` / `オプション` シートが作られる。
2. `syncMenuFromSeed` … 現行のメニュー14件とオプションを反映。実行ログに「メニュー 更新… / 追加…」と出ればOK。
3. `installTriggers` … 2日前18時・当日8時のリマインドを登録。

スプレッドシートに戻り、5つのシートができて `メニュー` に行が入っていることを確認します。

## 6. ウェブアプリとして公開
1. 右上「デプロイ → 新しいデプロイ」→ 種類の歯車で「ウェブアプリ」。
2. 次のユーザーとして実行 = **自分** / アクセスできるユーザー = **全員**。
3. 「デプロイ」→ 表示された **ウェブアプリのURL**(`https://script.google.com/macros/s/…/exec`)をコピー。
4. 動作の入口確認: ブラウザで `そのURL?action=menu` を開き、メニューのJSONが出れば成功(確認表1)。

> 以後コードを変えたら「デプロイを管理 → 鉛筆 → 新バージョン」で更新します(URLは変わりません)。

## 7. フロントをテスト環境につなぐ(ローカルのみ)
ローカルの `kohaku-booking/` で次を編集します。**コミット・push はしないでください**(確認後は必ず空に戻す)。
- `index.html` の `CONFIG.GAS_URL` に手順6のURL
- `admin.html` の `CONFIG.GAS_URL` に同じURL(必要なら `SITE_URL` も)

起動:
```bash
cd kohaku-booking
npx serve .
```
表示された `http://localhost:3000/index.html` と `admin.html` を開きます。

## 8. 動作確認
`docs/deploy-checklist.md` の確認表を次の順で進めます。
1. まず **1〜11**(メニュー表示、予約、二重予約、マイページ、管理画面、リマインド、終日予定)
2. 続けて **39〜44**(メニュー改訂後の表示・オプション)
3. 余裕があれば 20〜33(メニュー編集・クーポン)、分析は `docs/analytics-live-check.md`

うまくいかないときは、Apps Script の「実行数」でエラーを見るか、ブラウザの開発者ツール(F12)のコンソールを私に貼ってください。

## 9. 後片付け(確認が終わったら)
1. `index.html` / `admin.html` の `GAS_URL` を**空に戻す**(`git diff` で差分が無いこと)。
2. テスト予約の行は `予約` シートから削除、またはテスト用シートごと破棄。
3. 本番化するときは、**本番用のスプレッドシート・カレンダーで手順1〜6をやり直す**(`deploy-checklist.md` の「3. 本番切り替え」へ)。

## よくある詰まりどころ
| 症状 | 原因と対処 |
|---|---|
| 承認画面で進めない | 「詳細」→「(安全ではないページ)に移動」を押す |
| 予約が `bad_menu` になる | `syncMenuFromSeed` 未実行、または古いデプロイ。新バージョンで再デプロイ |
| メニューが予備(古い)表示 | `GAS_URL` が空、または `?action=menu` が失敗している(手順6-4で確認) |
| 予約しても空きが変わらない | `CALENDAR_ID` の誤り。カレンダーの共有設定ではなくIDを再確認 |
| 管理画面にログインできない | `ADMIN_PASSWORD` 未設定。`GAS_URL` が空だとパスワードは `demo` |
| メールが来ない | 迷惑メール確認。Apps Script の実行ログで `MailApp` のエラーを確認 |
