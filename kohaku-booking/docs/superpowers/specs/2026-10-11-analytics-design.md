# 売上・来店分析 設計書

日付: 2026-10-11 / 対象: `gas/Code.gs` `admin.html` `tests/`

## 1. 目的
予約シートの既存データから、売上・来店数・メニュー別・流入元別などを期間を指定して確認できる「分析」画面を管理画面に追加する。
データの追加入力や列の追加は行わない(既存データの集計のみ)。

合意済みの前提(オーナー確認済み):
- 「売上」は**状態が来店済の予約だけ**を実績として数える。確定(未来店)は「見込み」として別に表示し、過去日付なのに確定のままの予約は「未処理」として注意表示する
- 分析範囲は**基本セット**: サマリー / 推移 / メニュー別 / 流入元別 / 新規・再来

成功条件: 期間を選ぶと、その期間の売上(実績)・来店数・客単価・見込み・キャンセル率・前期間比・未処理件数が表示され、
推移とメニュー別・流入元別・新規/再来の内訳が、予約シートの内容と一致する。

## 2. 範囲外
曜日・時間帯別 / クーポン利用の分析 / 顧客別ランキング / CSV出力 / 目標との対比 / スタッフ別。
(必要になったら別の設計で追加する。)

## 3. 指標の定義
集計の単位はすべて予約の**日付**(来店予定日)で、期間は `from`〜`to`(両端を含む、JSTの日付)。

| 指標 | 定義 |
|---|---|
| 売上(実績) `sales` | 状態 `来店済` の予約の `合計金額`(割引後)の合計。金額が `null`(当日案内)の予約は含めない |
| 来店数 `visits` | 状態 `来店済` の件数 |
| 客単価 `avgSpend` | `sales` ÷ 金額が `null` でない来店数。該当が0件なら `null` |
| 金額未定 `unpriced` | 状態 `来店済` で金額が `null` の件数(売上に入らない) |
| 見込み `upcoming` | 状態 `確定` かつ `日付 >= 今日` の件数 `count` と金額合計 `amount`(`null` は金額に含めない) |
| 未処理 `pending` | 状態 `確定` かつ `日付 < 今日` の件数(「来店済」にされていない過去の予約) |
| キャンセル `cancelled` | 状態 `キャンセル` の件数 |
| キャンセル率 `cancelRate` | `cancelled` ÷(来店済 + 確定 + キャンセル)。分母0なら `null` |
| 前期間比 | 直前の同じ長さの期間(`from`の前日を終端とする、同じ日数)の `sales` と `visits` を `prev` として返し、画面で差(%)を表示。`prev` が0なら「—」 |

今日(`today`)は JST の `yyyy-MM-dd`。今日の予約は「見込み」に数え、「未処理」には数えない。

## 4. API(`gas/Code.gs`)
`adminAnalytics`(`adminAuth_` 必須、読み取り専用)

入力: `{from, to}`(`YYYY-MM-DD`)。
検証: 両方とも実在する日付、`from <= to`、期間の日数は400日以内。違反は `{ok:false, error:'bad_range'}`。

出力:
```
{ ok:true, from, to, today,
  summary:{ sales, visits, avgSpend, unpriced, upcoming:{count, amount}, pending, cancelled, cancelRate },
  prev:{ from, to, sales, visits },
  series:{ unit:'day'|'month', points:[{key, sales, visits}] },
  byMenu:[{name, visits, sales}],
  bySource:[{key, visits, sales}],
  visitType:{ first:{visits, sales}, repeat:{visits, sales}, unknown:{visits, sales} } }
```
- `series`: 期間が62日以内なら `day`(キーは `yyyy-MM-dd`)、超えれば `month`(キーは `yyyy-MM`)。**期間内の全ての日/月を、データが無くてもゼロで埋めて**返す。月別は期間の端の月も含める
- `byMenu`: `メニュー`(予約時のメニュー名)別に、`来店済` の件数と売上。売上の降順、同額は件数の降順、名前の昇順
- `bySource`: キーは `instagram_dm` / `instagram` / `line` / `web` / `other`(予約の `refSource`)。`refSource` が空のものは、受付経路 `admin` なら `admin`(管理画面から登録)、それ以外は `none`(流入元の記録なし)。件数が0のキーは返さない。売上の降順
- `visitType`: 予約時の自己申告 `初回`→`first` / `再来`→`repeat` / それ以外→`unknown`。`来店済` のみ
- 個人情報(名前・連絡先)は返さない。集計値のみ

純関数 `analyticsSummary_(rows, from, to, today) → 上記の summary〜visitType` に集計を切り出し、`vm` で単体テストする。
`prev` の期間計算は純関数 `prevRange_(from, to) → {from, to}`。日付の加減算は `Date` ではなく UTC の `Date.UTC` で日付文字列として行う(タイムゾーンずれを避ける)。
予約の読み込みは既存の `allRows_()` を使う。

## 5. 管理画面(`admin.html`)
- ナビ(`NAV` / `VIEWS`)に「分析」(キー `analytics`)を追加
- 期間: 「今月 / 先月 / 直近3か月 / 今年」のチップ + 「期間を指定」(開始日・終了日の日付入力、「表示」ボタン)。初期表示は「今月」
  - 今月 = 当月1日〜今日 / 先月 = 前月1日〜前月末日 / 直近3か月 = 今日を含む3か月分(当月を含め、2か月前の1日〜今日)/ 今年 = 1月1日〜今日
- 表示:
  - **サマリーカード**: 売上(実績・前期間比)/ 来店数(前期間比)/ 客単価 / 見込み(件数・金額)/ キャンセル率
  - **注意表示**: 未処理が1件以上なら「過去の予約のうち N件が来店済になっていません(売上に含まれていません)」、金額未定が1件以上なら「金額未定の来店が N件あります(売上に含まれていません)」
  - **推移**: 棒グラフ(外部ライブラリなし、棒の高さ/幅をCSSで比例表示)。日別または月別
  - **メニュー別 / 流入元別**: 表(名前・来店数・売上)と、売上に比例した横棒
  - **新規 / 再来**: 来店数と売上の内訳(「申告ベース」と注記)
- 該当データが無い期間は「この期間の予約はありません」を表示(サマリーは0表示でもよい)
- 取得失敗は既存の `failed` パターン(再読込ボタン)。`logout` で状態をクリア
- デモ表示(`GAS_URL` 空): デモの予約一覧(`demo`)から画面内で同じ集計を行う(GAS の `analyticsSummary_` と同じ定義)
- 表示する文字列(メニュー名など)は `esc()` で描画。金額は `yen()`。ゼロ除算・`null` は「—」

## 6. 安全性
- 管理系API(`adminAuth_` 必須)。読み取りのみで、シート・カレンダーに書き込まない
- 返すのは集計値のみ(個人情報なし)。メニュー名・流入元キーは `esc()` で表示
- 入力期間は検証し、400日を超える範囲は拒否する(大量集計の防止)

## 7. 既知の限界
- 売上は「来店済」にした分だけ。入力漏れは「未処理」として可視化するが、集計には入らない
- 新規/再来はお客様の自己申告(予約時の「初回/再来」)。顧客の実際の来店履歴による判定ではない
- 流入元は予約リンク(`?source=`)から来た予約だけに記録される。それ以外は「記録なし」
- 電話予約(管理画面から登録)の金額は手入力値で集計される
- 予約の `メニュー` は予約時の名前で保存されているため、メニュー名を後から変えると別の項目として集計される
- 予約が数千件を超える規模では、全件読み込みの集計が遅くなる(既存方針どおり、その時点で移行を検討)

## 9. 公開順序
GASを新バージョンでデプロイ → `admin.html` 公開。`setup` の再実行は不要(列の追加なし)。
旧 `admin.html` でも新GASで動く(新しいactionを呼ばないだけ)。新 `admin.html` を旧GASに向けると、分析画面が取得失敗の表示になるだけで他の機能に影響しない。
