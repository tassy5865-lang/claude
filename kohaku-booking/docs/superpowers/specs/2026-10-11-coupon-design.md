# クーポン管理 + 予約時の自動適用 設計書

日付: 2026-10-11 / 対象: `gas/Code.gs` `index.html` `admin.html` `tests/`

## 1. 目的
現状のクーポンは `クーポン`シートの内容をマイページに表示するだけで、来店時にコードを口頭で伝える運用である。
これを、(a) 管理画面からクーポンを発行・編集・無効化でき、(b) お客様が予約画面でコードを入力すると割引が自動で計算・記録される、ようにする。

合意済みの前提(オーナー確認済み):
- 割引の種類は**金額OFF と %OFF** の2種類
- 利用は**1人1回**(同じコードを同じメールで2回は使えない)。回数の上限設定は持たない
- コードの入力は予約の「内容のご確認」画面(マイページからの選択は範囲外)
- 割合は円未満切り捨て。コードの無効理由(期限切れ・対象外等)は利用者に区別して見せない

成功条件: 管理画面で発行したクーポンのコードを予約画面に入力すると割引後の合計が表示され、確定した予約の合計金額・クーポン・割引額が記録される。同じメールで2回目は使えず、予約をキャンセルすると再び使える。

## 2. 範囲外
管理画面の予約追加(電話予約)へのクーポン適用(スタッフが料金を手入力する従来運用のまま) / 利用回数・全体上限の設定 / 対象メニューの限定 /
「オプション1つ無料」型の割引 / マイページからのクーポン選択 / クーポンの削除(無効化で代替) / 割引の併用(1予約1コード)。

## 3. データ(列の追加は末尾のみ)
**`クーポン`シート**(7 → 9列): 既存 `コード, 名称, 内容, 対象メール(空=全員), 開始日, 期限, 状態(有効/無効/使用済)` の末尾に
`割引種別`(`金額` / `割合` / 空)と `割引値`(整数。金額なら円、割合なら 1〜100)を追加する。
- `割引種別`/`割引値` が空の既存クーポンは「割引未設定(表示のみ)」。予約時には適用できない
- 状態 `使用済` は以前の手運用の名残として残し、`無効` と同様に扱う(自動適用の対象外)

**`予約`シート**(26 → 28列): 末尾に `クーポン`(使ったコード)と `割引額`(円)を追加。`合計金額` は**割引後**の金額で保存する。
内部名は `couponCode` / `couponDiscount`。

**利用回数は保存しない**: 予約シートから数える。`クーポン` がそのコードで、メールが一致し、`予約ステータス` が `キャンセル` 以外の予約が1件でもあれば「使用済み」。
キャンセルすると自動で再び使える。

`setup`(`migrate_`)で見出しを最新にし、`ensureColumns_`(既存)が書き込み時にも列を足す。

## 4. 適用ルール(GAS)

### 4.1 コードの正規化と形式
前後の空白を除去し、全角英数字を半角にし、大文字化する。形式は `^[A-Z0-9_-]{3,20}$`(満たさなければ `bad_coupon`)。シート側のコードも同じ正規化で比較する。

### 4.2 判定(`couponApply_(coupons, rows, code, email, total, today)`、純関数)
1. コードが存在しない → `bad_coupon`
2. 状態が `有効` でない、`今日 < 開始日`、`今日 > 期限`、対象メールが空でなく予約のメールと不一致 → `bad_coupon`(理由は区別しない)
3. 割引種別/値が未設定(または `割合` で値が1〜100の範囲外、`金額` で値が1未満) → `coupon_not_applicable`
4. `total` が `null`(料金が当日案内) → `coupon_not_applicable`
5. 同じメール(正規化)で、非キャンセルの予約が同じコードを使用済み → `coupon_used`
6. 割引額 = `金額`: `min(割引値, total)` / `割合`: `floor(total × 割引値 / 100)`。結果 `total - 割引額 >= 0`
→ `{ok:true, code, name, discount, total: total - discount}`

### 4.3 予約確定時
`doPost` で、`calcBooking_` の後に `couponCode` があれば `couponApply_` を再実行し、その `total`・`discount` で保存する。
判定と書き込みは既存の `LockService` 下で行うので、同時予約でも二重に使えない。エラーなら予約せず `{ok:false, error}` を返す。
クライアントの割引額・合計は一切信用しない。

### 4.4 `couponCheck`(認証なし、確認画面の「適用」ボタン用)
入力 `{code, email, menuId, optionIds, minutes}` → `calcBooking_` で合計を出し、`couponApply_` で `{ok, name, discount, total}` を返す。予約は作らない。
**総当たり対策**: `CacheService` で、メール(正規化)ごとに10分10回・全体で10分100回を超えたら `{ok:false, error:'locked'}` を返す。
`doGet` ではなく POST の `action` として実装する(既存の `handleAction_`)。

### 4.5 通知
予約確認の本文(メール/LINE)に、クーポン利用時は「クーポン: CODE(−¥X)」の行を足す。合計は割引後の金額。

## 5. 管理API(`adminAuth_` 必須)
| action | 入力 | 出力 |
|---|---|---|
| `adminCoupons` | なし | `{ok, coupons:[{code,name,desc,target,from,to,status,type,value,used,state}]}`。`used` は非キャンセルの予約数(コード別)、`state` は計算した表示用状態(`active` / `upcoming` / `expired` / `disabled` / `unset`) |
| `adminCouponSave` | `{item, create}` | `{ok, code}` / `{ok:false, error, field?}` |

`item`: `{code, name, desc, target, from, to, status, type, value}`。
- `create:true`: コードが空なら `CP-` + 6桁の英数字を自動生成(既存と重複しない)。重複は `duplicate_code`
- `create:false`: コードで行を探して更新(コードは書き換えない)。無ければ `not_found`
- 検証(違反は `{error:'bad_field', field}`): コード `^[A-Z0-9_-]{3,20}$`(正規化後)/ 名称 1〜60文字 / 内容 200文字以内 / 対象メールは空かメール形式 /
  開始日・期限は空か `YYYY-MM-DD` の実在日で、両方あるとき `開始日 <= 期限` / 状態は `有効` `無効` `使用済` / 種別は空・`金額`・`割合` /
  値は種別があれば必須で、金額は 1〜1,000,000 の整数、割合は 1〜100 の整数(全角・カンマ・円記号は許容)
- セルは `'@'` 書式の文字列で保存する。保存後に My Kohaku のクーポン表示に使うキャッシュは無い(毎回シートを読む)

## 6. 予約サイト(`index.html`)
- 「内容のご確認」画面に、クーポンコードの入力欄と「適用」ボタンを置く。`couponCheck` を呼び、成功時は「クーポン: 名称(−¥X)/ ご請求額 ¥Y」を表示し、「外す」で取り消せる
- 適用後にメニュー・オプション・メールを変更して戻った場合は、適用を自動で解除する(再度「適用」が必要)
- 予約確定の payload に `couponCode`(適用中のみ)を付ける。確定時のエラー(`bad_coupon` / `coupon_used` / `coupon_not_applicable` / `locked`)は確認画面に戻して日本語で表示する
- My Kohaku のクーポン表示(`coupons_(email)`)に割引内容(「500円OFF」「10%OFF」)を併記し、**そのメールが使用済みのコードは出さない**
- デモ表示(`GAS_URL` 空)は、予備のクーポン(`WELCOME500` = 500円OFF、`AUTUMN10` = 10%OFF)で同じ画面遷移を再現する

エラー文言(`errMsg`): `bad_coupon`=「このクーポンコードはご利用いただけません」/ `coupon_used`=「このクーポンは既にご利用済みです」/
`coupon_not_applicable`=「このクーポンは今回のメニューにはご利用いただけません」/ `locked`=「しばらくしてからもう一度お試しください」。

## 7. 管理画面(`admin.html`)
- ナビに「クーポン」を追加(`NAV` / `VIEWS`)
- 一覧: コード・名称・割引内容(「500円OFF」「10%OFF」「割引未設定」)・期限・利用数、状態バッジ(有効 / 開始前 / 期限切れ / 無効 / 割引未設定)。上部に「＋ 発行」
- 編集シート: コード(新規時のみ入力・空なら自動、既存は表示のみ)/ 名称 / 内容 / 割引種別(金額OFF・%OFF・設定しない)/ 割引値 / 対象メール(空=全員)/ 開始日 / 期限 / 状態(有効・無効)
- 「設定しない」にしたクーポンは従来どおり表示専用。保存の失敗は `field` に応じた日本語メッセージ
- デモ表示は画面内のメモリのみ

## 8. 安全性
- 割引・合計・利用回数はサーバーが決める。公開APIは `couponCheck` と予約POSTのみで、コードの存在有無を区別して返さない(期間外・対象外・無効は `bad_coupon` に統一)
- `couponCheck` には試行回数の制限を付ける(4.4)
- 管理系は `adminAuth_` 必須。入力は GAS 側で再検証し、画面は `esc()` で描画、書き込みは文字列書式
- メールは正規化して比較する(大文字小文字・前後空白)

## 9. 既知の限界
- 利用回数の判定はメールで行うため、別のメールを使えば同じコードを再利用できる(全員向けコードは「1メール1回」)。電話番号等での名寄せはしない
- `couponCheck` の試行制限は `CacheService` に依存し、厳密なレート制限ではない(GASの制約)
- 管理画面からの予約追加(電話予約)には適用されない

## 11. 公開順序
GASを新バージョンでデプロイ → `setup` 再実行(列追加)→ `index.html` / `admin.html` 公開。
旧 `index.html` でも新GASで動く(クーポン欄が無いだけ)。新 `index.html` を旧GASに向けると `couponCheck` が `unknown_action` になり、確認画面で「適用」だけが失敗する(予約自体は成功する)。
