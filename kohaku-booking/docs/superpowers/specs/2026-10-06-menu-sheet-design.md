# メニュー管理のスプレッドシート化 — 設計書

日付: 2026-10-06 / 対象: `kohaku-booking`

## 目的
メニュー・料金・オプションを **スプレッドシートの `メニュー` / `オプション` シート**で管理し、オーナーがシートを直接編集するだけで予約サイトに反映されるようにする。
現在 `index.html` と `admin.html` にコピーがあり、ずれる原因になっている。あわせて、予約時の料金・所要時間を **GAS側で再計算**し、クライアントの値を信用しない。

## 合意済みの前提(オーナー確認済み)
- 編集方法は**シート直接編集**(管理画面の編集フォームは作らない。必要になったら後で追加)
- 料金・内容の正は**店主のメニュー表**(`自己紹介HP/アロマサロン琥珀/アロマサロン琥珀　メニュー.png`)
- GAS側での再計算を範囲に含める

## 範囲外
- 管理画面のメニュー編集フォーム / カテゴリ(`CATS`)のシート化(文言が固定のためコードに残す)
- 既存予約データの書き換え(予約シートには名前・金額が保存済みなので影響なし)

## 設計

### 1. シート
**`メニュー`**(1行=1メニュー。列の追加は末尾のみ)

| 列 | 内容 |
|---|---|
| メニューID | 英数字。既存予約・マイページの「同じメニューで予約」が参照するため**一度決めたら変えない** |
| 名前 | 表示名 |
| 所要分 | 数値(`omakase` 種別は無視) |
| 料金 | 数値(空=当日案内) |
| 説明 | 一行説明 |
| カテゴリ | `first,rec,aroma …` カンマ区切り(`CATS` のid) |
| グループ | サムネ色用 `aroma/facial/steam/pair/omakase` |
| 種別 | 空 / `pair`(オプションが2名分) / `omakase`(料金・時間を相談) |
| 表示 | `ON` / `OFF`(OFFは予約サイトに出さない。削除の代わりに使う) |
| 並び順 | 数値 |

**`オプション`**: オプションID / 名前 / 所要分 / 料金 / 表示 / 並び順

全セルは既存と同じく文字列書式で保存し、読み出し時に数値へ変換する。数値でない値は**その行を無効として除外**し、ログに残す。

### 2. API
- `GET ?action=menu`(認証なし) → `{ok:true, menu:[…], options:[…]}`。**表示=ON の行のみ**、並び順でソート。個人情報を含まない。
- 結果は `CacheService` に5分キャッシュ。シート編集後の反映は最大5分遅れる(許容)。
- `setup()` が両シートを作成し、**空のときだけ**初期データを書く(冪等。既存の編集は上書きしない)。

### 3. 予約時の再計算(`doPost` / `adminCreate_` / `reschedule`)
- `index.html` は `menuId` と `optionIds`(オプションID配列)を送る。**`total` / `minutes` はサーバーで計算**し、クライアント値は無視する。
  - 所要分 = メニュー所要分 + 選択オプションの所要分合計
  - 料金 = メニュー料金 + オプション料金合計 ×(`pair` なら2)。メニュー料金が空なら `null`
  - `omakase`: 所要分はクライアント値を `[60, 90, 120]` の許可リストで検証
- 未知の `menuId`、`表示=OFF` のメニュー/オプション → エラー `bad_menu`(フロントの `errMsg` に日本語を追加)。
- 予約シート・カレンダーに入れる `menuName` / オプション名もサーバーが決める。
- 管理画面の `adminCreate_` は**手入力の料金・所要分を許可したままにする**(電話予約の特例対応のため)。ただし `menuId` があるときはサーバー計算値を初期値として返せるようにはしない(今回は変更しない)。
- 日時変更(`reschedule`)は所要分を既存予約の値から取っており、料金に触れないので変更なし。

### 4. フロント
- `index.html`: 起動時に `menu` を取得し `MENU` / `OPTIONS` を差し替える。**取得失敗時・デモモード(`GAS_URL` 空)は現在埋め込みの配列を予備として使う**(`npm test` はこのまま通る)。読み込み中は「メニューを読み込み中…」を表示。
- `admin.html`: 同じ `menu` API を使い、コピーを廃止。デモ時は予備配列。
- 予備配列は、初期データと**同じ内容**に更新する(下記)。

## エラー処理・安全性
- シート読み取り失敗/空 → `menu` は `{ok:false,error:'menu_unavailable'}`、フロントは予備配列で動く(予約は予備の `menuId` で送られ、サーバーがシートで検証。シートが空なら `bad_menu`)。
- 公開シートの内容(料金表)は公開情報。個人情報は載せない。
- `menu` はキャッシュあり。`doPost` の再計算はキャッシュではなく**シートを直接読む**(料金改定直後の食い違い防止)。

## テスト
- `npm test`(デモ): 予備配列で既存フローが通ること。メニュー表の新規2件が表示されること。`optionIds` がペイロードに入ること。
- 追加テスト: `menu` API をスタブして、取得した内容で一覧が描画されること / 取得失敗で予備に落ちること。
- GAS: `check:gas`(構文)。純粋関数(`calcBooking_`)は Node で単体テストできる形にする。実機(シート・カレンダー)は**未確認のまま**と明記する。

## オーナー確認結果(2026-10-06)
1. ペア「蒸し+フット/頭ほぐし30分」の所要分は70分で確定
2. 単品のよもぎ蒸し・まこも蒸しは非表示(OFF)のままでよい
3. 琥珀サイトの「初回限定 ¥10,000」は予約サイトにも入れる → `first100`。カテゴリは `first`(はじめての方)のみ。説明に「初回限定・通常¥12,000」と表示する。
   サーバー側で初回かどうかの強制はしない(`初回/再来` は自己申告のため。確認は店舗運用で行う)。
