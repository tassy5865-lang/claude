# 本番化チェックリスト(GAS実機確認つき)

**順序が重要**: GASを先に更新 → `setup` 再実行 → フロント(`index.html`)公開。逆だと予約が `bad_menu` で失敗する。
いきなり本番にせず、**テスト用スプレッドシート+テスト用カレンダー**で一通り確認してから本番に切り替える。

## 0. 事前に決めること(オーナー確認)
- [ ] 通知先メール `OWNER_EMAIL`
- [ ] 専用カレンダーを使うか(使うなら `CALENDAR_ID`)
- [ ] 予約サイトの公開URL `SITE_URL`
- [ ] 管理画面の置き場所(予約サイトと別URL・推測されにくいもの)。**公開中の `demo` パスワードはGAS_URL設定後は無効**になるが、管理画面を置く場所は決めておく
- [ ] 仮置きの値: 定休日=水 / 営業10-20時 / 準備15分 / 同時1件 / キャンセル期限24h / `NOTICE` 文言
- [ ] LINE連携を初回から使うか(使うなら LINE Developers の LIFF 準備が必要。後回しも可。手順は「4. LINE連携を本番に切り替える」)

## 1. GAS(テスト環境)
1. テスト用スプレッドシート作成 → 拡張機能 → Apps Script → `gas/Code.gs` と `gas/appsscript.json` の内容を反映
2. `CONFIG` を編集(`OWNER_EMAIL` / `SITE_URL` / 必要なら `CALENDAR_ID`)
3. スクリプト プロパティに `ADMIN_PASSWORD`(LINEを使うなら `LINE_CHANNEL_ACCESS_TOKEN` / `LINE_LOGIN_CHANNEL_ID` / `LIFF_ID`)
4. `setup` 実行 → 権限承認。`予約`/`顧客`/`クーポン`/`メニュー`/`オプション` シートが作られ、メニューに初期データが入る
5. `installTriggers` を一度実行(2日前18時・当日8時のリマインド)
6. デプロイ → ウェブアプリ(実行=自分 / アクセス=全員)→ URL を控える

## 3. 本番切り替え
1. 本番用スプレッドシート/カレンダーで 1〜2 を繰り返す(または同じものを本番に昇格)
2. メニュー・料金をメニュー表画像と突き合わせる(正はメニュー表画像)
3. `index.html` / `admin.html` の `CONFIG.GAS_URL`(必要なら `LIFF_ID`)を設定してコミット・公開
4. 管理画面を別URLに置き、`noindex` を確認
5. 最後に本番で予約を1件→キャンセルして後始末

## 4. LINE連携を本番(店主の公式LINE)に切り替える
テスト用チャネルでの実機確認(2026-10-25)は完了済み。**LINEの `userId` はプロバイダーごとに別の値**なので、テストで連携したお客様は本番に引き継がれない(本番では連携し直し)。テスト用のチャネル・LIFFは流用せず、本番用に作り直す。

### 4-1. 事前に決める・確認する(店主)
- [ ] 本番の公式LINEの管理権限(店主のアカウントで操作、またはあなたを管理者に追加してもらう)
- [ ] 公式LINEの**あいさつメッセージ**と**応答メッセージ**をオフにしてよいか(お客様に見える設定)
- [ ] プランのメッセージ数の上限を確認。1予約あたり最大3通(確認・2日前・当日。日時変更・キャンセルは別に1通)。月の予約数 × 連携率 × 3通が上限に収まるか

### 4-2. LINE Developers(店主のプロバイダーに新規作成)
1. プロバイダーを作る(本番の公式LINEと**同じプロバイダー**に作る。別だとボット連携ができない)
2. **Messaging API**: 本番の公式LINEで有効化 → チャネルアクセストークン(長期)を発行。Webhookはオフのまま(使わない)
3. **LINEログイン**チャネルを作成 → 公開ステータスを「公開済み」に → **チャネルID**を控える
4. **LIFF**を追加: エンドポイントURL=本番の予約サイト(`index.html`)の公開URL(`https://` 必須)、スコープ=`openid`、サイズ=Full → **LIFF ID**を控える
5. LINEログインチャネルと公式LINEを**ボット連携**する(友だち追加オプションはオン)

### 4-3. 本番GASと予約サイトに設定する
変える値(テスト → 本番):

| 場所 | 項目 | 値 |
|---|---|---|
| 本番GAS スクリプト プロパティ | `LINE_CHANNEL_ACCESS_TOKEN` | 本番Messaging APIの長期トークン |
| 同上 | `LINE_LOGIN_CHANNEL_ID` | 本番LINEログインのチャネルID |
| 同上 | `LIFF_ID` | 本番のLIFF ID |
| 同上 | `DEBUG_LINE_EMAIL` | **設定しない**(確認用の `debugLinePush` を本番で動かさないため) |
| `index.html` の `CONFIG` | `LIFF_ID` | 本番のLIFF ID |
| `index.html` / `admin.html` の `CONFIG` | `GAS_URL` | 本番GASの `/exec` URL |
| 本番GAS `CONFIG` | `SITE_URL` | 本番の予約サイトURL |

- トークン・チャネルIDはスクリプト プロパティだけに入れる。コードやチャットに書かない
- **テスト用のLIFF ID・GAS URLを本番の `index.html` に入れたままにしない**(`kohaku-booking-test/` にだけ入れる)

### 4-4. 公開の順序
1. 本番GASに最新の `gas/Code.gs` を貼り、**新バージョン**でデプロイ(`setup` は列追加がなければ不要)
2. `installTriggers` を実行済みか、左メニューの「トリガー」で確認(`remind2DaysBefore` 毎日18時・`remindToday` 毎日8時)
3. その後に `index.html` / `admin.html` を公開(逆だと `bad_menu` 等で失敗する)
4. LIFFのエンドポイントURLが本番URLになっているか確認

### 4-5. 本番での最終確認(店主のLINEで)
| # | 確認項目 | 期待 |
|---|---|---|
| L1 | 本番サイトを開く | 「LINEで通知を受け取る」ボタンが出る |
| L2 | 予約 → My Kohaku で連携コード発行 → LINEで連携 | 「LINE連携が完了しました」がLINEに届く。`顧客`シートの `LINE userId` が埋まり、`LINE通知` が `許可` |
| L3 | もう1件予約 | 確認通知が**LINE**に届く(メールではない) |
| L4 | 管理画面でキャンセル(通知オン) | キャンセル通知がLINEに届く |
| L5 | マイページから日時変更 | 日時変更の通知がLINEに届く |
| L6 | 来店24時間を切った予約を開く | 変更・キャンセルのボタンが出ず、「LINEにてご連絡ください」と表示される |
| L7 | 店主のLINEで公式アカウントをブロック → 予約 | 通知がメールに切り替わり、`LINE通知` が `停止` になる。解除して連携し直すと `許可` に戻る |
| L8 | 後始末 | テスト予約をキャンセル。`顧客`シートのテスト行(店主のLINE分)を確認 |

### 4-6. うまくいかないとき
- 連携しても通知がLINEに来ない: `LINE_CHANNEL_ACCESS_TOKEN` の名前・値(前後の空白)、`顧客`シートの `LINE userId`、連携時と予約時のメールが同じか
- 連携後に友だちにならない: LINEログインチャネルと公式LINEのボット連携(4-2の5)
- LIFFが開かない: エンドポイントURLが `https://` の本番URLか、LINEログインチャネルが「公開済み」か
- LINEの応答を調べたい: テスト環境で `debugLinePush`(`DEBUG_LINE_EMAIL` を設定して実行。`push:` と `profile:` の2行が出る。プロフィール取得が404=ブロックまたは友だち解除)
- 関数名の末尾が `_` のもの(`lineFriendGone_` など)は、Apps Scriptの関数選択に出ない。Ctrl+Fで検索して存在を確認する

## 既知の注意点
- GASを変更したら「デプロイを管理」から**新バージョン**で更新(URLは変わらない)
- 列を追加したときは `setup` を再実行(並び替え・削除は禁止)
- メニューシートを空にすると初期データが再投入される
- 秘密情報(パスワード・トークン)はスクリプト プロパティのみ。コードに書かない
