# 本番化チェックリスト(GAS実機確認つき)

**順序が重要**: GASを先に更新 → `setup` 再実行 → フロント(`index.html`)公開。逆だと予約が `bad_menu` で失敗する。
いきなり本番にせず、**テスト用スプレッドシート+テスト用カレンダー**で一通り確認してから本番に切り替える。

## 0. 事前に決めること(オーナー確認)
- [ ] 通知先メール `OWNER_EMAIL`
- [ ] 専用カレンダーを使うか(使うなら `CALENDAR_ID`)
- [ ] 予約サイトの公開URL `SITE_URL`
- [ ] 管理画面の置き場所(予約サイトと別URL・推測されにくいもの)。**公開中の `demo` パスワードはGAS_URL設定後は無効**になるが、管理画面を置く場所は決めておく
- [ ] 仮置きの値: 定休日=水 / 営業10-20時 / 準備15分 / 同時1件 / キャンセル期限24h / `NOTICE` 文言
- [ ] LINE連携を初回から使うか(使うなら LINE Developers の LIFF 準備が必要。後回しも可)

## 1. GAS(テスト環境)
1. テスト用スプレッドシート作成 → 拡張機能 → Apps Script → `gas/Code.gs` と `gas/appsscript.json` の内容を反映
2. `CONFIG` を編集(`OWNER_EMAIL` / `SITE_URL` / 必要なら `CALENDAR_ID`)
3. スクリプト プロパティに `ADMIN_PASSWORD`(LINEを使うなら `LINE_CHANNEL_ACCESS_TOKEN` / `LINE_LOGIN_CHANNEL_ID` / `LIFF_ID`)
4. `setup` 実行 → 権限承認。`予約`/`顧客`/`クーポン`/`メニュー`/`オプション` シートが作られ、メニューに初期データが入る
5. `installTriggers` を一度実行(2日前18時・当日8時のリマインド)
6. デプロイ → ウェブアプリ(実行=自分 / アクセス=全員)→ URL を控える

## 3. 本番切り替え
1. 本番用スプレッドシート/カレンダーで 1〜2 を繰り返す(または同じものを本番に昇格)
2. メニュー・料金をメニュー表画像と突き合わせる(正はメニュー表画像)
3. `index.html` / `admin.html` の `CONFIG.GAS_URL`(必要なら `LIFF_ID`)を設定してコミット・公開
4. 管理画面を別URLに置き、`noindex` を確認
5. 最後に本番で予約を1件→キャンセルして後始末

## 既知の注意点
- GASを変更したら「デプロイを管理」から**新バージョン**で更新(URLは変わらない)
- 列を追加したときは `setup` を再実行(並び替え・削除は禁止)
- メニューシートを空にすると初期データが再投入される
- 秘密情報(パスワード・トークン)はスクリプト プロパティのみ。コードに書かない
