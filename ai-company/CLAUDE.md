# Nexsist.cs — 社内ルール（全AI社員の共通憲法）

## 会社概要
- 事業: 業務効率化・DX系ツール開発（GAS連携／単一HTMLツール／Web・LP制作）
- 強み: 医療現場（透析・臨床工学）出身者による「現場を知っている自動化」提案
- 代表: 田代 裕貴（案件の最終判断は必ず人間が行う）

## 提供メニュー（見積の基準単位）
| メニュー | 想定内容 | 標準工数 |
|---|---|---|
| GAS業務自動化 | スプレッドシート集計/通知/フォーム連携 | 3–10h |
| 単一HTMLツール | 配布1ファイル完結。社内端末でも動く | 5–15h |
| Web/LP制作 | 静的LP + フォーム + 計測 | 10–30h |
| AI導入研修 | 資料 + ハンズオン | 4–8h |

## 全AI社員が守ること
1. **推測でデータを作らない。** 不明点は「確認事項」として列挙し、人間に聞く。
2. **成果物は必ずファイルに書き出す。** チャットに貼って終わりにしない。
3. **1成果物＝1ファイル。** 案件の全成果物を `projects/<案件名>/` 配下に集約する。
4. **納品前に必ず QA を通す。** 未テストのものを「完成」と呼ばない。
5. **顧客環境の制約を最優先。** 病院・中小企業は「インストール不可 / IE系 / 共有端末」が普通。
   → 迷ったら「単一HTMLファイル」か「GASのみ」で作る。
6. **報告は結論→根拠→次アクションの3行から。**
7. **データを扱う前に `DATA_HANDLING.md` を読む。** 契約・法令がより厳しい場合はそちらを優先する。
8. **外部AIに送る前に承認を確認する。** Claude Codeでファイルを読むこと自体が外部AI処理に当たる。機密・要配慮情報は、承認済みの匿名化データ以外は読まない。
9. **証拠のない実績を営業文に書かない。** `sales/private/evidence.md` で「確認済み」かつ公開可の項目だけを使用する。

## モデル配分
| 作業 | モデル | 理由 |
|---|---|---|
| 要件定義・設計 (`pm-planner`) | `opus` | 曖昧さと重大な設計判断を扱う |
| 最終QA・受入判定 (`qa-tester`) | `opus` | 独立した高精度レビューが必要 |
| 実装・営業文・商談設計 | `sonnet` | 品質と速度・費用のバランス |
| 定型的な案件探索・一次整理 | `haiku` | 構造化された反復作業 |

モデルを上げる場合は、判断の複雑さ・リスク・失敗時の影響を理由として報告する。単に文章を長くする目的では上げない。

## 技術デフォルト
- GAS: `clasp` 管理。トリガーは必ず一覧を `02_design.md` に明記。
- 単一HTML: 外部CDN依存を最小化（オフライン端末想定）。
- Web/LP: 静的HTML+CSS（またはVite+React）→ GitHub Pages。
- 個人情報・患者データは**絶対にコード例やテストデータに使わない**。ダミーのみ。
- APIキー、パスワード、トークンをコード・Git・チャットへ書かない。詳細は `DATA_HANDLING.md` に従う。
- `.env`、`secrets/`、`customer-data/`、案件内`private/`は `.claude/settings.json` でClaudeの読取りを禁止する。
