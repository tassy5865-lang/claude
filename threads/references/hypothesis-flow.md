# 仮説検証（メニュー⑦）

## 基本
1回の検証で変える条件は原則1つ。結果はユーザーが手入力した数値だけで判定する。
「伸びる/伸びない」ではなく「この条件を変えたら、この指標がどう動いたか」を確かめる。

## 仮説を立てる（1問ずつ）
| # | 聞くこと | 選択肢の例 |
|---|---|---|
| Q1 | 何を確かめたいか | 冒頭の型／問いかけの形／文量／投稿時間帯／画像の有無／その他 |
| Q2 | 今のやり方 | Q1で選んだ条件について、普段どうしているか（例：問いかけなら「どう思う？」で終える／付けない） |
| Q3 | 新しく試すやり方 | Q2を踏まえた選択肢を出す（例：二択で聞く／体験を聞く）。Q2と同じものは選択肢に入れない |
| Q4 | なぜそう思うか | 自分の過去投稿から／攻略情報から（⑥の結果）／なんとなく |
| Q5 | 見る指標 | 返信数／表示回数／いいね／再投稿・引用／フォロワー増減 から1つ（補助指標は1つまで） |
| Q6 | 比べる基準 | 普段の投稿の平均／同じ期間の別パターン |
| Q7 | 期間・本数 | 例：1週間・各パターン3本。わからなければ推奨を出す |

検証計画を出す前に、Q2（今のやり方）とQ3（新しいやり方）が必ず決まっているようにする。計画を出した後に「今はどうしていますか？」と聞き直さない。

## 検証計画の出力
```
仮説：〇〇を△△に変えると、□□（指標）が増える
変える条件：〇〇（1つ）
固定する条件：テーマの種類、文量、投稿時間帯 など
見る指標：□□（補助：××）
比べ方：パターンA（今まで通り）とパターンB（変更）を各〇本
期間：〇〇まで
記録表：投稿日／パターン／本文の冒頭／□□／××／メモ
```

## 結果を判定する（ユーザーが記録を貼ったら）
1. 記録表を整理し、パターンごとに並べる。
2. 区分して出力する：
   - **データから言えること**：数値の差そのもの
   - **言い切れないこと**：本数が少ない、条件がずれた投稿がある、など
   - **次の一手**：続ける／条件を変えて再検証／やめる、のどれかを1つ提案
3. 差が小さい・ばらつきが大きい場合は「差があるとは言えない」と伝える。

## 禁止
- 記録にない投稿・数値を補って判定する。
- 1回の結果で「この型が正解」と結論づける。
