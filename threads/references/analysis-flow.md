# 投稿分析（メニュー③④）

## 基本
同じ指標同士だけを比較する。
データから直接言えること、公式情報と照らして言えること、仮説、判断不能を分ける。
最後に改善仮説を1つに絞り、次回変更する条件も原則1つにする。

## 集める情報（1問ずつ）
| # | 聞くこと | 補足 |
|---|---|---|
| Q1 | 投稿本文 | 貼り付け。画像・動画があれば内容を一言で |
| Q2 | 手元にある数値 | 表示回数、いいね、返信、再投稿、引用など。持っているものだけ。「ない」でも進める |
| Q3 | 比べる基準 | 普段の投稿の平均／直近の似た投稿／特になし |
| Q4 | 投稿した日時と、その前後の状況 | 連続投稿、話題の出来事など。わからなければ飛ばす |
| Q5 | 投稿者の感覚 | 「なぜ伸びた/伸びなかったと思うか」。仮説の材料として使い、事実とは区別する |

## ③伸びなかった投稿で見る点
- 冒頭で誰向けの話かわかるか。
- 読者が「自分は？」と考える場面があるか（`rewrite-flow.md` のコメント設計3点）。
- 返信しやすい入口があるか。
- 基準と比べて本当に低いのか（基準がない場合、「伸びなかった」は判断不能と伝える）。

## ④伸びた投稿で見る点
- 何が再現できる要素で、何が偶然の要素か（時事ネタ、他者の引用など）を分ける。
- 返信の中身（ユーザーが貼れる場合）：どんな種類のコメントが多かったか。
- 「伸びた理由」を1つに決めつけない。再現を試す条件を1つ選ぶ。

## 出力の形
| 区分 | 内容 |
|---|---|
| データから言えること | 提示された数値・本文からそのまま言えることだけ |
| Meta公式情報と照らして言えること | `meta-rules.md` の確認手順を通ったものだけ。なければ「該当なし」 |
| 仮説 | 「〜かもしれない」で書く。根拠も一言添える |
| 判断不能 | データが足りず言えないこと。何があれば判断できるかも書く |
| 次回検証 | 変える条件1つ、変えない条件、見る指標、比べる基準 |
| 改善版 | ③は改善した投稿案を1つ。④は同じ型で別テーマの投稿案を1つ |

## 禁止
- 提示されていない数値を推測で書く（「おそらく表示回数は〇〇程度」など）。
- 表示回数と返信数のように、違う指標同士を比べて結論を出す。
- 1投稿の結果だけで「この型は伸びる/伸びない」と断定する。
