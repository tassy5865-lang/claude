# 琥珀サイト 管理画面 設計書

作成日: 2026-10-15 / 対象: `自己紹介HP/アロマサロン琥珀/`

## 目的
店主(非エンジニア)が、琥珀サイトの文章・料金メニュー・写真・お知らせを、ブラウザ上で直接編集して公開できるようにする。成功条件は「店主が一人で、GitHub を触らずに、5分以内に料金1行を直して公開できる」こと。

## 決定事項(ユーザー合意済み)
- 利用者: 店主(真弓さん)など非エンジニア
- 編集範囲: 文章 / 料金・メニュー表 / 写真の差し替え / お知らせ・営業日の告知(新設)
- 保存方式: 管理画面から GitHub API で `index.html` と画像を直接コミット(サーバー不要)
- リポジトリ: 琥珀サイトを専用リポジトリ `kohaku-site` に分離し、トークンの権限を琥珀だけに限定する(案A)

## 非目標
- ユーザーごとのアカウント管理、複数人の同時編集、履歴の閲覧UI(履歴は git に残るのみ)
- レイアウト・デザイン・CSS・JSON-LD・GA4・オープニング動画の編集
- 予約システム(kohaku-booking)との連携

## アーキテクチャ
```
kohaku-site (新リポジトリ, GitHub Pages)
├─ index.html / styles.css / main.js / images/ ...   既存サイト(静的HTMLのまま)
├─ tools/check_site.py                                既存の検査
└─ admin/
   ├─ index.html   管理画面(noindex、1ファイル完結)
   ├─ admin.js     取得・編集・差分・コミット
   └─ config.json  暗号化済みトークン(PBKDF2+AES-GCM)・リポジトリ名
```
- 公開サイトは今までどおり静的HTML。JSなしでも全文が読め、SEOも変わらない。
- 管理画面は GitHub Contents API で `index.html` を取得 → 目印付き箇所だけ書き換え → 同じAPIでコミット(Pagesが約1分で再公開)。

## 編集の仕組み
- `index.html` の編集可能箇所に `data-edit="<key>"` を付ける。管理画面はその要素の中身(テキスト / 画像の src・alt)だけを書き換え、他のHTMLには触れない。
- 料金表は `<ul class="price-list">` を行単位(名前 / 金額)で編集する。行の追加・削除・並べ替えが可能。金額は半角数字で入力し `¥10,000` 形式に整形する。
- 写真は `data-edit-img` 付きの `<img>` のみ差し替え可能。ブラウザ内で縮小・圧縮(長辺1600px、JPEG品質0.82)してから `images/` にコミットする。`width`/`height` 属性は読み込んだ画像から更新する。alt は必須入力。
- お知らせ帯は新設要素 `data-edit="notice"`(ヘッダー直下)。空なら `hidden` にして非表示。
- 編集中の下書きはブラウザ内(localStorage、使えなければメモリのみ)に保持。「公開する」で差分の要約を表示し、確認後にコミットする。
- 右側に iframe プレビューを置く(取得した HTML を `srcdoc` で表示)。

## 認証と安全性
- 店主はパスワード1つでログイン。GitHub のトークンは fine-grained PAT(対象: `kohaku-site` のみ、Contents: Read and write のみ)で、パスワードから PBKDF2(SHA-256、60万回)で鍵を導出し AES-GCM で暗号化して `config.json` に置く。復号はブラウザ内で行い、トークンは保存しない(セッション中のメモリのみ)。
- 限界(明記): 管理画面は公開URLにあるため、暗号文は誰でも入手できる。強度はパスワードの強さに依存する。長いパスフレーズを使い、トークンに有効期限(90日)を設けて期限前に差し替える。権限が琥珀リポジトリのコンテンツ書き込みに限られるため、最悪でも被害は琥珀サイトの改ざん(git で復元可能)に留まる。
- 管理画面には `noindex`、robots 除外を入れる。
- 書き込み前に `check_site.py` 相当の検査(料金形式・リンク・必須文言・alt)をブラウザ側でも実行し、通らなければ公開を止める。
- 取得した最新 `sha` を使って更新する。他の変更と衝突した場合は書き込みを中止し「最新を読み込み直してください」と案内する(上書きしない)。
- 失敗時は何も書き込まず、原因を平易な日本語で表示する。

## リポジトリ分離(実装計画の最初の段階)
1. `kohaku-site` を新規作成し、琥珀サイト一式(`images/` `tools/` 含む。元画像・動画の未追跡素材は含めない)を移す。
2. Pages を有効化し、新URL(`https://tassy5865-lang.github.io/kohaku-site/`)で表示と GA4 計測を確認する。
3. `canonical`・`og:url`・`og:image`・JSON-LD の `url` を新URLに更新する(現状 canonical 未設定のため追加扱い)。
4. 旧リポジトリ側の `自己紹介HP/アロマサロン琥珀/` は、新URLへのリダイレクトページに置き換える。ポートフォリオ・自己紹介HP・ai-consult-lp などのリンク元を新URLへ更新する。
5. 旧フォルダの削除・リネームは OneDrive 同期の事故を避けるため git で行う。

## 検証
- `tools/check_site.py` を管理画面の公開前チェックとして流用し、CI(GitHub Actions)でも push 時に実行する。
- 管理画面のロジック(HTMLの部分書き換え、料金整形、差分生成)は DOM 上の単体テストで確認する。
- 公開前に、実機(PC とスマホ)で「料金1行を変更 → 公開 → 反映確認 → 元に戻す」を通しで確認する。

## 未解決・要確認

- お知らせ帯の見た目(色・位置)は実装時にサイトのデザインに合わせて決める

## 計画段階での補正(2026-10-15)
実装計画(`docs/superpowers/plans/2026-10-15-kohaku-admin.md`)の作成時に、既存コードを読んで次を補正した。
- 編集範囲の目印は `data-edit` 属性ではなく **HTML コメント**(`<!--edit:KEY-->…<!--/edit:KEY-->`)にする。写真のみ `data-photo` 属性。DOM を再シリアライズすると `index.html` 全体が整形し直され、JSON-LD・GA4 が変わる恐れがあるため。
- `index.html` には canonical / og:url / og:image / JSON-LD の url が**すでにある**(旧URL)。「追加」ではなく「新URLへの置換」。
- 保存は画像ごとの `PUT contents` ではなく、Git Data API で `index.html` と画像を **1 コミット**にまとめる。
- 検査ルールは `tools/rules.json` に集約して Python と JS で共有する。固定の料金リスト(`PRICES`/`ROWS`)は、店主が料金を直すと検査が落ちるため廃止し、形式検査に置き換える。
